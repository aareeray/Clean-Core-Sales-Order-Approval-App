## Activation Order

```
1. ZSO_P_REJECT         (abstract entity — no dependencies)
2. ZSO_R_REQ_H (BDEF)   (depends on ZSO_P_REJECT, ZSO_R_REQ_H view, ZSO_R_REQ_I view)
3. ZSO_BP_REQ_H (Class) (generated by BDEF; implementation goes in locals_imp)
```

---

## Step-by-Step in ADT

### Step 1: Create Abstract Entity ZSO_P_REJECT

1. File → New → Other → ABAP Repository Object → Core Data Services → **Data Definition**
2. Name: `ZSO_P_REJECT`
3. Description: `Action Parameter: Reject Sales Order Request`
4. Package: `Z_SALES_APPROVAL`
5. Template: **"Define Abstract Entity"**
6. Paste content from `ZSO_P_REJECT.ddls.asddls`
7. **Ctrl+F3** to activate

### Step 2: Create Behavior Definition ZSO_R_REQ_H

1. Right-click on `ZSO_R_REQ_H` (the CDS view) in Project Explorer
2. New → **Behavior Definition**  
   *(OR: File → New → Other → ABAP Repository Object → Business Services → Behavior Definition)*
3. Implementation Type: **Managed**
4. The editor opens with a generated stub — replace entirely with `ZSO_R_REQ_H.bdef.asbdef`
5. **Ctrl+F3** to activate

> ⚠️ On activation, ADT will prompt: **"Create the referenced class ZSO_BP_REQ_H?"** → Click **Yes**.  
> This auto-generates the class shell in the project.

### Step 3: Implement the Behavior Class ZSO_BP_REQ_H

ADT creates a skeleton class. You need to:

1. Open `ZSO_BP_REQ_H` in ADT
2. The class has `local types` — open the **"Local Types"** tab (bottom of editor)
3. Delete the generated stub in Local Types
4. Paste the full content from `ZSO_BP_REQ_H.clas.locals_imp.abap`
5. **Ctrl+F3** to activate

> **ADT file structure for a BDEF class:**
> - `ZSO_BP_REQ_H.clas.abap` → The global class body (keep as ADT generates it)
> - `ZSO_BP_REQ_H.clas.locals_imp.abap` → Your local handler class (paste here)

## Common Activation Errors and Fixes

| Error | Cause | Fix |
|---|---|---|
| `ZSO_P_REJECT not found` | Abstract entity not activated first | Activate ZSO_P_REJECT before BDEF |
| `Draft table ZSO_DREQ_H not found` | Draft tables not created | Create from Day 1 tables first |
| `Method SUBMIT not found in ZSO_BP_REQ_H` | Local class not pasted | Paste locals_imp content in Local Types tab |
| `keys[] access: line not found` | Empty keys table in reject | Wrap in `READ TABLE keys` with OPTIONAL |
| `cl_abap_context_info not released` | Old system | Use `sy-datum` / `sy-uzeit` as fallback |
| `strict(2): non-released API` | Any non-released class used | Check each class against ABAP Cloud API list |

## setChangedAt: cl_abap_context_info Alternative

If `cl_abap_context_info` causes a strict(2) error:

```abap
" Replace cl_abap_context_info calls with:
DATA: lv_date TYPE sy-datum,
      lv_time TYPE sy-uzeit.
lv_date = sy-datum.
lv_time = sy-uzeit.
" Combine into utclong using released CL_ABAP_UTCLONG=>COMBINE
DATA(lv_ts) = cl_abap_utclong=>combine(
  date = lv_date
  time = lv_time ).
" Then use lv_ts as ChangedAt value
```

## Status Flow Summary

```
[DRAFT] --submit--> [PENDING] --approve--> [APPROVED]  (terminal)
                             --reject---> [REJECTED] --resubmit--> [DRAFT]
```

- `submit`:   DRAFT only. Sets Approver = MANAGER (<10k) or DIRECTOR (>=10k)
- `approve`:  PENDING only. Requires `Approver = sy-uname`
- `reject`:   PENDING only. Requires `Approver = sy-uname` + non-empty RejectionReason
- `resubmit`: REJECTED only. Requires `CreatedBy = sy-uname`. Clears Approver + RejectionReason
